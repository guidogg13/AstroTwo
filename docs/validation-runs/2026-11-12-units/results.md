# Units written by AstroTwo after D05-6 — interoperability check (sprint D11, 2026-11-12)

Candidate **1.0.0 build 7** (commit `c43d622`; code unchanged since then: commits `2a6a63b` and this one touch only documents and measurement files). **No network** for any check in this folder. Tools: Astropy 8.0.1 (project environment), **STILTS 3.5-6 / STIL 4.3-6** from the local `topcat-full.jar` (run with the HTTP/HTTPS proxy set to `127.0.0.1:9`, so no network access), and its unit library **unity 1.1** (by the author of the IVOA VOUnit recommendation) for VOUnit and FITS validity. Decision **D05-7** proposed from these results (`mdfiles/05-comandi-sessione.md` §13, `mdfiles/decisioni-aperte.md`).

## Where AstroTwo writes unit texts (checked in the code of `c43d622`)

| Output | Who writes the unit text | Reachable from the 1.0 interface |
|---|---|---|
| Result JSON, profile ECSV (column `unit`, a text column), profile PDF | `unit_json` / `unit_text` of AstroTwo (`commands.py`, D05-6) | yes |
| Profile SED VOTable (`object.export sed_votable`, `object.send_sed` over SAMP) | Astropy, fixed columns `deg`, `um`, `Jy`, `mag` | yes |
| Catalog VOTable 1.4 (`export_table` → `samp.send_table`, SAMP `table.load.votable`) | **Astropy** (`votable_from_table`), not `unit_json` | yes (SAMP) |
| Catalog FITS table and ECSV (`export_table(..., "fits" / "ecsv")`) | **Astropy** (`table_to_hdu`, ECSV writer) | **no** (library function of the `14`; no interface command) |
| FITS image `BUNIT` (`save_fits`, HiPS tile cache) | the original text of the source, unchanged | not as an export command |
| SAMP `coord.pointAt.sky` | degrees as numbers, no unit text | yes |

A catalog column can hold a unit only if its source text is valid FITS or VOUnit for Astropy (`13` `_normalize_units`), or if the user declares an angular unit for the position columns (`catalog.set_columns`; the catalog panel offers `deg`, `hourangle`, `rad`, `arcmin`, `arcsec`; a command or the assistant can give any angular unit, e.g. `cycle`).

**How TOPCAT/STIL reads them** (`stilts-read.txt`): STIL keeps the unit attribute **as text, unchanged** (`15deg`, `6.2831853rad`, `earthMass`, `electron / s`), with no conversion. `votlint unit=true ucd=true version=1.4` reports **no unit problem** on any VOTable written here (`15deg` and `6.2831853rad` are valid VOUnit: a numeric factor is allowed). How TOPCAT uses `15deg` for sky axes (hours or degrees) was not checked: it needs the TOPCAT interface (megatest, **to be verified**).

### Findings

1. **Catalog VOTable / SAMP, position columns declared in `hourangle`:** written `unit="15deg"`. Valid VOUnit (unity: recognised and recommended), exact, read back by Astropy as the same unit without warnings; TOPCAT shows the text `15deg`.
2. **Same, declared in `cycle`** (only by command or assistant, not offered by the interface): written `unit="6.2831853rad"`, valid VOUnit but with a **truncated factor** (relative error −1.14·10⁻⁹; read back by Astropy as 0.9999999988573335 cycle). This is the D05-6 defect («never a truncated factor») in an output that D05-6 did not cover.
3. **Catalog FITS table** (not reachable from the interface in 1.0): `hourangle`, `cycle` (and `earthMass`, `earthRad`, `jupiterMass`, `jupiterRad`, `AB`, which cannot be catalog units) → Astropy `UnitScaleError`, the export fails with a non-module error; `electron / s`, `dex` → `TUNIT` **omitted silently** (Astropy's warning is suppressed in `_write_fits_file`).
4. **Units lost on input, then missing in the VOTable sent over SAMP:** the Gaia DR3 flux columns arrive as `'electron'.s**-1` (valid VOUnit, quoted unknown unit). `13` re-reads the unit from Astropy's *generic* text `electron / s`, which is neither FITS nor VOUnit → the column gets no unit, the warning `UNIT_UNRECOGNIZED` says «not valid in FITS nor in VOUnit» (not true for the source text), and the exported **VOTable (SAMP) and FITS have no unit** for these 6 columns; only the ECSV keeps `electron / s`. Same loss, correctly flagged, for non-standard source units (`days`, `Earth Mass`, `Earth Radius` of the NASA Exoplanet Archive). Values are never changed. (`catalog_export_units.py`, output in `stilts-read.txt`.)
5. **Result texts** (JSON, profile ECSV/PDF): `earthMass`, `earthRad`, `hourangle`, `cycle`, `AB`, `dex` are Astropy names, unknown units for VOUnit and FITS; `electron / s`, `km / s`, `mas / yr` (from `unit_text`) are Astropy generic syntax, valid in neither. These files have no unit standard to follow (the ECSV unit is a text column), and Astropy and `unit_from_json` read all of them back exactly (point b).
